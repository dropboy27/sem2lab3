# Лабораторная работа 3
## Итерируемые коллекции и генераторы-фильтры

* **Цель:** Освоить создание пользовательских итерируемых коллекций и реализацию ленивых генераторов-фильтров для работы с доменными объектами.

* **Библиотеки:** `pytest`, `typing`, `datetime`, `random`, `time`, `unittest.mock`

* **Допущения:**
  - Коллекция задач (`TaskQueue`) хранит объекты `Task` и поддерживает итерацию через `__iter__`.
  - Фильтрация по приоритету - сравнение (меньше / больше / равно заданному значению, 1–5).
  - Фильтрация по статусу - включение (`'новая'`, `'в работе'`, `'завершена'`) или исключение задач с указанным статусом.
  - Фильтрация по идентификатору - сравнение (меньше / больше / равно заданному `id`).
  - Все методы фильтрации реализованы как **генераторы** (`yield`), что обеспечивает ленивое вычисление.
  - Базовая модель `Task` с дескрипторами и свойствами наследуется из предыдущей лабораторной работы без изменений.

* **Чему я научился:**
  - Реализация **итерируемого класса** (`TaskQueue`) с методом `__iter__`, позволяющим обходить коллекцию в цикле `for`.
  - Использование **генераторов** вместо списков для ленивой фильтрации: методы `filter_by_priority`, `filter_by_status`, `filter_by_id` возвращают генераторные объекты.
  - Понимание разницы между **жадной** (возврат списка) и **ленивой** (генератор) фильтрацией, а также преимуществ последней при работе с большими коллекциями.
  - Реализация протокола `TaskSource` для унифицированного получения задач из разных источников (файл, генератор, API‑заглушка).
  - Расширение консольного меню: добавление интерактивного раздела фильтров с вложенными условиями.
  - Написание модульных тестов с `pytest` для проверки корректности итерации и генераторов-фильтров.

### Алгоритм решения
1. Класс `Task` сохранён из лабораторной работы 2 с дескрипторами и свойствами:
   - `ReadOnlyInt` – проверяет тип, положительность и запрещает изменение.
   - `ReadOnlyString` – проверяет тип, непустоту и запрещает изменение.
   - `PriorityField` – проверяет диапазон [1, 5] и запрещает изменение.
   - `StatusField` – допускает изменение только среди разрешённых значений.
   - `ShortDescription` – non‑data дескриптор, возвращает первые 10 символов описания.
2. Создан класс `TaskQueue` - коллекция-обёртка над списком задач:
   - `add_task(task)` - добавляет задачу в конец очереди.
   - `__iter__` - делает коллекцию итерируемой, позволяя использовать `for t in tasks`.
   - `__bool__` - позволяет проверить очередь на пустоту через `if not tasks`.
3. Реализованы три генератора-фильтра:
   - `filter_by_priority(priority, condition)` - `condition`: 1 (меньше), 2 (больше), 3 (равно).
   - `filter_by_status(status, condition)` - `condition`: 1 (с указанным статусом), 2 (без него).
   - `filter_by_id(id, condition)` - `condition`: 1 (меньше), 2 (больше), 3 (равно).
4. Для единообразного получения задач сохранён протокол `TaskSource`.
5. Реализованы три источника: `FileTaskSource`, `TaskGenerator`, `ApiTaskSource`.
6. В `main.py` расширено консольное меню: добавлен пункт **5 - фильтры** с интерактивным выбором поля и условия.

### Интересные тест-кейсы
- Итерация по пустой `TaskQueue` - цикл `for` завершается без ошибок, ни одна задача не возвращается.
- `filter_by_priority(3, 1)` - возвращает только задачи с приоритетом строго меньше 3.
- `filter_by_priority(3, 2)` - возвращает только задачи с приоритетом строго больше 3.
- `filter_by_priority(3, 3)` - возвращает только задачи с приоритетом ровно 3.
- `filter_by_status('завершена', 1)` - возвращает только завершённые задачи.
- `filter_by_status('завершена', 2)` - возвращает все задачи, кроме завершённых.
- `filter_by_id(10, 3)` - возвращает задачи с `id == 10`.
- Передача несуществующего условия фильтра (например, `condition=4`) - ожидаемое `ValueError`.
- Ленивость генераторов: результат `filter_by_priority(...)` вычисляется только при итерации.
- Чтение из несуществующего файла - ожидаемое исключение `FileTaskSourceNotFound`.
- Генерация задач через `TaskGenerator` - все поля соответствуют допустимым диапазонам.
- Имитация задержки в `ApiTaskSource` - проверка, что `time.sleep` вызывается.

### Инструкция к использованию

#### Запуск приложения
```bash
python -m src.main
```
Меню

- **1 - Прочитать задачу из файла** - запрашивает имя файла, ожидает строки формата:
  `<id> <описание> <приоритет> <статус>`
  (например: `1 Do_homework 3 новая`). Некорректные строки пропускаются с выводом ошибки.

- **2 - Сгенерировать задачи** - запрашивает количество, создаёт задачи со случайными данными.

- **3 - API заглушка** - запрашивает количество, имитирует сетевую задержку и возвращает задачи.

- **4 - Увидеть задачи** - выводит все накопленные задачи в полном или кратком формате.

- **5 - Фильтры** - позволяет отфильтровать задачи по одному из полей:
  - **По приоритету** - введите значение (1–5) и условие (меньше / больше / равно).
  - **По статусу** - введите статус (`новая`, `в работе`, `завершена`) и условие (с ним / без него).
  - **По идентификатору** - введите `id` и условие (меньше / больше / равно).

- **6 - Выход** - завершение программы.
